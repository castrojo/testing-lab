# Lab Bandwidth Reduction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce avoidable upstream and cross-node image traffic while preserving digest-pinned QA coverage and making registry failures explicit.

**Architecture:** Keep Zot as the only registry path for cluster image pulls, remove public-registry fallback from the node mirror configuration, and reduce redundant image-poll fan-out before changing test coverage. Zot remains on-demand and cache-backed; retry and sync-scope changes are bounded to observed repositories and validated against live metrics.

**Tech Stack:** Kubernetes manifests, ArgoCD GitOps, Argo Workflows, Zot, containerd registry mirrors, Prometheus/cAdvisor, `just lint`, pytest.

## Global Constraints

- All durable cluster changes are made in Git-tracked `manifests/` or `argo/workflow-templates/` and reconciled by ArgoCD.
- Do not use `kubectl apply` for `manifests/` or `argo/workflow-templates/`.
- Keep Zot on-demand caching and digest pinning; do not replace the cache with direct upstream pulls.
- Do not remove an upstream registry until its repository prefixes are covered by the observed consumer inventory.
- Preserve existing QA suites and schedules unless a measured duplicate trigger is removed.
- Verify the live resource after ArgoCD reconciliation before submitting or resubmitting workflows.
- Run `just lint` after manifest or WorkflowTemplate changes.

        yaml.safe_load(Path("manifests/image-poll-akmods-44.yaml").read_text()),
